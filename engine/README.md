# fend 内核补丁

基于 fend **1.5.9**，上游提交 `71f3fcd796ca87074a94452162ca0a7044ca5da3`。保留上游 MIT 许可；公开发布包包含 `THIRD_PARTY_NOTICES.txt`。

`fend-core.patch` 包含两处 Rust 修复及五组原生回归测试：

- `logN` 支持大于等于 2 的整数底数，例如 `log7(8)`、`log3 27`。在局部参数和已保存变量之后解析，所以已有同名函数优先。用包含内置 `ln` 字面量的函数表达式计算，支持嵌套、函数别名和变量序列化；字符串、注释不会被改写。`log`、`log2`、`log10` 保持原有行为。底数 0、1 报错，负数参数继续遵循 fend 的复数对数规则。
- 分数指数的分子或分母超过 1024 时，先检查能否精确开根；能精确计算的结果仍走整数运算。其余情况使用浮点近似，避免先算不可承受的巨大中间幂，修复 `10^(log(5))`、`2^(log2(5))`、`exp(ln(5))` 等报错或卡住的问题。近似结果保留 `approx.` 标记，精度约为双精度浮点数的 15 位有效数字；超出支持范围时报错，不输出伪造的精确结果。

网页、PWA 和 APK 使用同一份修复后的 WASM。UI 不增加控件。原有精确整数运算、短分数指数和单位运算继续由 fend 处理。

## 重新构建

普通构建只需要 Node.js，直接使用已提交的产物。仅修改 Rust 补丁或同步上游内核时需要：

- Rust **1.88.0**，并安装 `wasm32-unknown-unknown` target。
- `wasm-bindgen-cli` **0.2.129**，与上游 Cargo 锁文件一致；可用 `WASM_BINDGEN` 指定可执行文件。
- `curl`、`tar`、`patch`，以及访问 GitHub / crates.io 的网络。

```sh
npm run engine:build
npm run test:web
```

使用 `npm run engine:build -- --check` 可在不覆盖产物的情况下验证重新构建的字节与清单一致。

脚本校验工具版本、固定源码归档的 SHA-256 及补丁摘要，在临时目录应用补丁，运行 fend-core 的原有测试和补充测试，再用 `--locked` 构建 WASM。生成的 wasm-bindgen 模块附加 `worker-entry.js`，替换 `assets/` 中原有的工作线程及 WASM，并更新清单摘要。编译时重映射本机目录，发布产物不包含维护者的主目录路径。

产物保留上游文件名，整个资源组由 `version-assets.mjs` 按实际内容生成版本目录，因此 PWA 会取得新内核。未保留旧内核副本，也不在用户设备上下载第二套计算器。

补丁或工作线程入口变更时，须先更新 `vendor-manifest.json` 中的 `localEngine.sources` 摘要，再显式重新构建；普通构建遇到摘要不符会停止。源码、补丁、工具版本及产物摘要都记录在该清单，便于上游修复后移除对应补丁。上游界面文件仍保留原始内容，界面及缓存补丁只作用于 `www/`。
